# Tiger Style v1.1 Hardening Decisions

This page locks canonical decisions for v1.1 hardening and serves as the policy reference for
follow-on contract, validator, workflow, and adoption updates.

## D-01: Tier-0 Planning Artifacts Are Optional By Default

- Tier 1-3: task packet and test plan are required before implementation.
- Tier 0: task packet and test plan are optional by default.
- Evidence packet remains required for all tiers.
- Repository policy may adopt stricter behavior (for example, requiring Tier-0 planning artifacts).

## D-02: Core And Language Enforcement Must Match Contract Scope

- Core gates always run.
- Language quality gates run for active language contracts.
- CI must not report success while active language quality gates are skipped.

## D-03: Validators Must Enforce Semantic Completeness

- TDD validation requires state-correct Red -> Green -> Refactor sequencing.
- Evidence validation requires semantic completeness for Red, Green, Refactor, and Risk Tier
  sections.
- Heading-only or placeholder-only evidence is non-compliant.

## Canonical Precedence

When artifacts disagree, apply:

1. Core contract text.
2. Enforcement implementation (`scripts/*`, `.github/workflows/*`).
3. Documentation and examples.

If any mismatch is found, treat it as a compliance defect and fix forward before merge (or use a
timeboxed, explicitly approved exception with compensating controls).
